# GPT-6 Astra harness adoption

## Outcome

Run `gpt-6-astra` through the existing agent harness with native Responses tool
calls, conversation continuity, output policy enforcement, and attributed
execution spending. Local models are required for the harness; cloud models
augment local inference and never replace it.

## Baseline

PR #687 establishes the per-completion provider policy boundary. PR #682 supplies
the permit-bound MCP proxy and portable trust foundation. Integrate each after
its required checks pass. Derived provenance (#686), sentinel training (#680),
and local GGUF evaluation (#625) remain independent work.

## Provider contract

- Use the Responses API with the exact `gpt-6-astra` model and `OPENAI_API_KEY`.
- Support documented reasoning efforts; omit unsupported sampling parameters.
- Preserve native call IDs and opaque reasoning items across tool results and
  later turns without displaying opaque state as text.
- Support completion, structured output, and bounded streaming with cancellation.
  Surface refusals, incomplete responses, protocol faults, and API errors.
- Preserve total input, cached input, visible output, and reasoning usage without
  double counting. Keep credentials out of diagnostics.

## Harness and routing

- Register model metadata and wire the binary, CLI, router, and LLM features.
- Require a local inference backend and provisioned local models before starting
  the agent harness, even with cloud credentials or an explicit cloud selection.
  Keep the default model and intent decomposition local. Authorize cloud
  augmentation through the existing spend policy.
- Keep Responses state in assistant history and pair every native tool result
  with its call ID. Pass all returned output through the #687 guard.
- Record execution attempts against the shared budget, including retries, with
  actual model attribution (#587). Verify that default agent builds retain local
  inference alongside Astra; provider-only library builds remain modular.

## Validation

Use deterministic HTTP fixtures for request shape, native tool continuation,
schema output, usage, errors, fragmented streaming, cancellation, and policy
withholding. Add harness regressions and a credential-gated live smoke test.
Run formatting, debug build, Clippy, focused tests, and required security suites.
Use #357's cross-provider contract direction without depending on its full scope.

Async tools and WebSocket mid-turn steering are later harness capabilities.
They are not implied by initial synchronous tool-loop support.

## Integration progress — September 7

The active implementation is `feature/gpt-6-astra` (PR #688), in the main
checkout. The Codex worker bridge remains a separate follow-up on
`feature/codex-worker-bridge`.

The output-policy boundary from #687 is already in the branch. The trust-layer
foundation from #682 was integrated locally after its reported checks passed;
manifest and chat-session conflicts preserve cloud feature propagation,
noninteractive startup, native tool history, and terminal stream events.

The review corrections enforce cloud authorization on orchestrator planning and
adjustment, send the output allowance priced by preflight on every affected
dispatch path, bound paired tool results in CLI and chat sessions, and retain
configured cloud models for mixed-provider subtasks. Cached local subtask models
remain usable. Regression fixtures cover policy denial without dispatch, output
limits, Unicode truncation, and mixed-provider selection.

The local-first requirement supersedes the earlier cloud-only startup and routing
assumptions. Cloud keys no longer skip local provisioning, missing local backends
are refused for harness commands, and intent decomposition stays local even with
approved cloud augmentation. Utilities remain available to provision the device.

Validation passed after the local-first correction: formatting, full debug build,
Clippy with `-D warnings`, 502 router tests, five orchestrator planning tests,
five startup-policy tests, eight first-run tests, 12 intent-analysis tests, and
173 trust-foundation tests. Provider validation passed 18 unit tests and nine
deterministic HTTP fixtures; paired-result and Unicode-boundary regressions pass.
The credential-gated live smoke test was not run.

Required security checks passed: protocol vulnerabilities (12 passed, one
pre-existing signature-timing test ignored), mock-provider tests (four passed),
E2E security (10 passed), local CLI security (10 passed, two binary-inspection
checks skipped), and DLP/PII (17 passed, including taint-egress tests). These
targeted checks do not establish workspace coverage. The macOS debug linker
reported its unwind-table-size warning. Changes remain local to the branch.
